# 分類辞書の保守

## 正本・ビルド・検査

- 語彙・語義・語形・関連語の唯一の正本はリポジトリ直下の `dictionary.json`。語彙登録の依頼はウェブ版への反映まで行う。ローカルの辞書Markdownや編集差分ファイルを管理しない。言語規則は `../ラフカ語文法.md` が規範。
- 作業前に `git pull --ff-only` で最新の正本にする。`../tools/web_source.py` は直下の `dictionary.json` を読み込み・検証するだけで、取得キャッシュは持たない。
- `lexicon.py` はウェブ正本の検証・読み込み、`entry_model.py` は表示用データ、`build.py` は生成物を担当する。再生成で保存済みの語形を計算し直したり、関連語を別表から復活させない。
- 既存の項目ID・語形・所有者の編集を保持する。このフォルダーの HTML・`data.json`・収録一覧はGit管理外の確認用生成物。公開する `../index.html`・`../version.json` は `export_pages.py` で直下の `dictionary.json` から更新する。
- 変更後は `python3 -m unittest -v` と `python3 build.py --check`。画面を変更した場合は `ui.test.cjs` と `editor.ui.test.cjs`、編集・保存処理を変更した場合は `node editor.test.cjs` でも確認する。

## 語形・品詞・収録範囲

- ウェブ辞書の明記形は規則補完より優先し、文法書の古い個別語の記述は最新の登録形に照合して更新する。構文注記・用例も文法書の用法説明へ反映し、旧稿に説明がないだけで未規定と扱わない。一般規則に合わない形も直ちに誤りとはせず、個別形か資料内の不一致かを確認する。母音幹の語尾と子音接合は文法1.4・2.1.5・2.3.2–2.3.7に従う。性・語幹・語形に欠落を残さず、存在しない数・人称の形は欄自体を作らない。新しい規則を定める場合は文法書に記載してから辞書と実装を揃える。
- 名詞の交替型と語幹末の種類を分ける。形容詞には名詞のⅠ・Ⅱ型を流用しない。
- 数の制限は正本の「不可算」「単数のみ」「複数のみ」に従う。存在しない数の語形を生成・表示・検索しない。manča・bidašta・höri は男性・複数のみの独立名詞として扱い、曲用語尾を根拠に性を変えない。
- 品詞は名詞・代名詞・動詞・形容詞・連体詞・副詞・前置詞・接続詞・小辞・間投詞。基数・序数・疑問は機能、接辞・慣用句は項目種別として分ける。数詞の品詞は文法7章の一致・格支配に従う。ganに比較級等を自動生成しない。
- 文法から補足する接辞・語形には参照節を付ける。未採用案は本辞書へ取り込まない。
- 見出しは個別の語・慣用句・生産的な接辞に限る。「等」付きの総称や「＋与格」のような構文説明を語彙として登録しない。意味もその語固有の語義にする。
- 非生産的・化石的な接辞（`-ča`、`-t-`）は独立登録しない。`horča` などの個別の派生語は保持する。
- 規則どおりの「〜すること」を表す動名詞は独立した見出しにしない。独自の意味・用法を獲得し、語彙化した根拠がある場合だけ名詞として登録する。単なる語形の明記、日本語の名詞訳、定型句中の用例だけを語彙化の根拠にしない。根拠未確認の `gessad`・`humad`・`sibad` は元の動詞の語形として扱う。

## 分類と語義

- 人名のタグは「人名」に統一する。「借用人名」「固有人名」は資料の区分として保持し、タグにしない。人名の語義欄は「カタカナの読み（男性人名／女性人名）」に統一し、語源の説明を載せない。祖語型は別欄に保持する。
- タグ体系は `taxonomy.json` を正本とし、語全体の品詞・性・交替型・曲用型・活用型・数の制限と、語義ごとの機能・可算性・使用域・待遇を分ける。親分類は検索に使い、子分類と重複表示しない。名詞の個別交替型と動詞の不規則活用を区別する。曲用型は語尾の見た目でなく曲用設定・明記形で判定する。
- 語義タグは任意フィールド `senseTags` の `{meaning, tags}` として保存し、各 `meaning` は意味欄の正規化された1語義と一致させる。編集画面では語義を別行で扱い、移動・削除・公開・バックアップでも分類をその語義と一緒に扱う。`taxonomy-review.json` は分類移行時の点検記録で、後日の所有者の編集を上書きしない。
- タグを変更した場合は `node taxonomy.test.cjs` と `taxonomy.ui.test.cjs` で語義の対応、階層検索、品詞の条件、保存・再生成を確認する。
- 意味欄は1行に1語義とし、複数の語義は番号付きの別項目として表示する。同じ語義の訳語は半角カンマ `,` と読点 `、` の両方で区切れ、表示と新たな保存は `, ` に統一する。語義間の改行は保存・再編集・公開・バックアップ・再生成でも保持し、関連語の候補でも区別する。各語義のどの訳語も完全一致・前方一致・部分一致で検索できるようにする。既存のカンマから異なる語義を推測して自動分割しない。`meaning.ui.test.cjs` と公開保存を含む `public-relations.ui.test.cjs` で確認する。
- 訳語はその語義に合う同義語・表記違い・読みを補う。上位語・下位語や、意味の異なる関連語を検索用に混ぜない。人名の表示は従来の読みと性別を保持する。意味の括弧注記と前後の「〜」「～」を除いた訳語でも検索できるようにし、表示の語義・注記は保持する。全項目の語義点検記録は `meaning-review.json`。記録はその時点の点検結果であり、その後の所有者の編集を上書きするために使わない。

## 編集・補完・関連語

- 追加・編集画面では `morphology.js` で活用・曲用を自動補完する。名詞の斜格幹・曲用語尾、動詞の現在／強語幹、形容詞の性別語幹を指定でき、手入力の例外・削除した語形は優先する。設定は項目の任意フィールド `inflection` に保存し、再生成時も保持する。
- 補完規則を変更したら `node morphology.test.cjs` と `morphology.ui.test.cjs` を確認する。現行文法の規則に合わせ、既存語形を勝手に置き換えない。
- 関連語の「派生語」「派生元」は「派生」に統一し、「類義」「対義」を選択できるようにする。関係の名称変更で参照先ID・語義・語形を変えない。旧下書きとバックアップの読み込み・競合照合でも表記を統一する。集合名詞と対応する単数の関係は保持する。
- 「派生・類義・対義」は相互関係として扱う。片側での追加・種類変更・削除・取り消しを相手側にも反映し、両側の変更を下書きとGitHubへ同時に保存する。相手側の競合を上書きしない。関連語の確認には `relation.ui.test.cjs` も実行する。
- 公開された関連語とその相互リンクは未ログインでも表示する。「保存して公開…」は編集画面から公開対象の一覧を開き、「公開する」でGitHubへ反映する。端末だけの保存は「下書きに保存」と明示する。公開済みの語彙を未ログイン・別端末で閲覧する検証には `public-relations.ui.test.cjs` を使う。
- 単語の削除も所有者限定。下書きの削除は `{before:元の語彙,after:null}`、公開後は `dictionary.json` の全語彙から除去し、`deletedIds` に記録し、再生成で復活させない。削除先への関連リンクはすべて除去する。公開前の取り消し・バックアップ・競合検出を維持し、削除は `editor.test.cjs`・`public-relations.ui.test.cjs`・`test_edit_data.py` で確認する。

## 認証と公開

- 公開前に最新mainを pull し、`export_pages.py` でその `dictionary.json` を使う。公開先の編集を空のファイルや古いコピーで上書きしない。手元と公開先の編集が競合したら両方の語義・語形を確認して統合する。画面で編集された語のIDは見出し・品詞を変えても維持する。
- GitHubの公開先はラフカ語専用の `velvet-orbit-731/lafca-dictionary`。`enerlevip` は別プロジェクトなので、ラフカ語の公開・更新先にしない。
- ZpDICとの同期・書き出し・配布は行わない。辞書の編集とGitHub保存、編集内容のバックアップを維持する。
- 編集はGitHubユーザーID `337917858` の所有者に限定する。編集開始・公開保存時に `/user` と専用リポジトリの所有者・権限を検証する。匿名時は下書きを適用せず、認証情報は永続保存しない。認証の変更後は `node owner-auth.ui.test.cjs` も実行する。
